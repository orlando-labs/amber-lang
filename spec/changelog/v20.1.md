# Amber v20.1 Changelog

Status: current changelog for the v20.1 reference implementation baseline.

## Amber v20.7/v20.8 Language Update

- Added the combined spread/name-key revision to the main language spec.
- Fixed `*` / `**` as contextual spread markers for calls and collection
  literals, with eager finite expansion and conditional spread entries.
- Revised ordinary `Map` / `HashMap` to be name-indifferent for `Symbol` and
  `Str` textual keys, with exact-key behavior moved to `StrictMap` and
  `StrictHashMap`.
- Revised keyword spread to validate keyword-convertible keys from maps and
  kwargs views, reporting `KeywordArgumentError` for invalid or duplicate
  keyword names.

## AMBEREXT-001 Inline Conditionals and Conditional Collections

- Added parser support for inline conditional expressions:
  `if condition then consequent else alternative`.
- Rejected C-style ternary syntax with
  `AMB-SYN-INLINE-TERNARY-CSTYLE` and missing inline `else` with
  `AMB-SYN-INLINE-IF-MISSING-ELSE`.
- Added conditional `if` / `unless` elements for list/set literals and
  conditional map entries, preserving `if` vs `unless` in AST/HIR.
- Lowered conditional collection construction through ordinary branch/jump
  bytecode and existing `MAKE_LIST`, `MAKE_SET`, and `MAKE_MAP` instructions.

## W12 Documentation/Spec Sync

- Added a generated anchor map for the canonical README, main spec, project
  layer, engineering notes, and changelog files.
- Added registry SHA-256 inventory for the token, prelude, diagnostic, opcode,
  bytecode section, and runtime error registries.
- Added a W0-W15 implementation status dashboard with release-gate state.
- Added migration notes documenting that W12 does not change runtime or artifact
  formats.
- Added `make spec-sync-check` and `tools/spec_sync.py check` to detect stale
  anchor maps and broken local Markdown links.

## W11 Modern Profile Baseline

- Closed `W11.1`-`W11.6` as metadata-first modern profiles: capabilities,
  effects, replay, schema/table, Wasm/accelerator, AI-agent tooling, contracts,
  privacy/lineage, and workflows.
- Added `CAPS`, `EFCT`, `OBSV`, `RPLY`, `SCMA`, `TABL`, `WASM`, `ACCL`,
  `AGNT`, `CNTR`, `PRIV`, and `WFLW` bytecode/profile sections.
- Exposed focused CLI checks for each profile lane and runtime mirror hooks for
  profile validation state.

## W13 Compiler-Contract Closure Slice

- Added the prelude registry minimum W13 inventory and expanded runtime error
  registry inventory.
- Added binder top-level assignment pre-scan so module-cell exports resolve
  before source-order module init execution.
- Added `..` token/parser support, inclusive range lowering through
  `Range.new(..., inclusive_end: true)`, `in` lowering to `contains?`, and
  `and` / `or` bytecode control-flow lowering.
- Added bytecode verifier operand/range checks and per-code CFG
  initializedness dataflow for the W13 `UNINIT < INIT_VALUE` lattice.
- Added VM initialized-bit tracking for frame locals/module cells with
  `NameError` on runtime uninitialized reads and GC root scanning that skips
  uninitialized slots.
- Added the unified `CALL` packet path for closures, class constructors, and
  ordinary objects that expose an instance-side `call` method, with call-cache
  guards over positional count, canonical keyword shape, block presence,
  world epoch, and method version.
- Added structured source trace frames carrying module id, byte start/end,
  line/column start/end, and generated-span kind.
- Tightened W13 source rules for shebang/comments and numeric literal forms,
  including separators, base prefixes, exponents, and constant-pool
  canonicalization.

## W14 Build/Bootstrap/Conformance Closure

- Added `amber.build.v1` manifest parsing and stable build summary JSON.
- Added `amberc build <amber.build.json>` with deterministic multi-module
  `.amberbc` output, manifest-relative source labels, incremental cache keys,
  verified cache reuse, and CLI smoke coverage.
- Added B2 stdlib bootstrap metadata through ordinary bytecode compilation,
  `amber.bootstrap.layer` attributes, deterministic stdlib ABI hashes, and
  ABI-pinned stdlib dependency entries for ordinary build modules.
- Added `.amberbc` `PROF` metadata for required, optional, and forbidden
  profile features plus profile flag normalization.
- Added runtime loader rejection for unsupported required profile features with
  `UnsupportedProfileError`.
- Added the `M11` conformance bundle, which extends the cumulative corpus with
  compile-all verification over compile/disasm/run/load fixtures.

## W15 Native-Readiness Metadata Closure

- Added explicit `NativeCodeObject.slowpath_table` metadata for runtime stubs,
  reflective stubs, patchpoint guard misses, and frozen-world invalidation
  fallback.
- Added exception-edge safepoints/root maps and hardened `native-verify`
  diagnostics for missing slowpaths, invalid slowpath ranges, missing exception
  handler root maps, and missing invalidation fallback.
- Tightened frozen-image verification so embedded `amber.native.v1` summaries
  must advertise W15 readiness guards as well as frozen-world requirements.

## Post-W15 Artifact CLI Surface

- Added public `amberc metadata <file.amberbc> --json` and
  `amberc verify <file.amberbc> --json` commands over serialized bytecode
  artifacts, keeping the existing `amberbc-*` commands as compatibility
  aliases.
- Normalized corrupted-bytecode verifier output for the public `verify --json`
  command so failures still produce `amber.bc.verify.v1` JSON on stdout.
- Added `make test` smoke coverage for metadata, successful verification, and
  corrupted-artifact verification failure.
- Added focused `ISS-092` runtime coverage for duplicate keyword value-read
  ordering, canonical keyword-shape cache hits, block-presence cache guards,
  and keyword-call cache invalidation after `world_epoch` changes.
- Added focused `ISS-093` module-loader coverage for live import-alias
  snapshots across export-cell readiness/failure transitions, sticky failed
  init, and repeated cyclic-init attempts.
- Added focused `ISS-094` GC/root-map coverage for callee and back-edge
  safepoint roots, rooted local/shared cycles, exception-unwind pin release,
  native allocation/call/back-edge root maps, and native trampoline argument
  rooting.
- Documented the implemented `net.http` Phase 7 basic server slice:
  `Server`, `ServerRequest`, and `ServerResponse` over plaintext HTTP/1.1
  loopback/TCP, with one request per accepted connection, explicit close, and
  focused `vm_net_http_tests` coverage.
- Added the core-stdlib breadth batch (spec §13.11/§13.12): sequence
  `join`/`sum`/`product`/`flattened`/`compact`/`zip`/`partition`/`tally`/
  `each_with_index`/`last`/`count(value)`/`count |x|:` with the mutating pairs
  `Array#flatten!`/`Array#compact!`; `Map#dig` and the discouraged `Map#fetch`
  alias; `Int`/`Float` `abs`/`divmod`/`clamp` plus `Int`
  `even?`/`odd?`/`gcd`/`lcm`/`upto`/`downto`; the pure `-ed` string family
  (`upcased`/`downcased`/`capitalized`/`titlecased`/`swapcased`/`humanized`/
  `underscored`/`camelized`/`dasherized`/`trimmed`/`ltrimmed`/`rtrimmed`/
  `reversed`/`replaced`) with Unicode simple-case mapping over the curated v1
  scripts, and string `*`/`ljust`/`rjust`/`index`/`rindex`/`lines`/
  `count(sub)`/`[]`/`slice`. Unknown selectors on `Range` and `LazySeq`
  receivers now raise rescuable `NoMethodError` instead of a terminal
  `VMError`, and bare property access on `LazySeq` routes through the builtin
  send path. Covered by six new `corpus/run` fixtures.
- Fixed three long-standing dispatch/pattern defects: (1) `not` and the
  `unless` lowering were unimplemented at runtime (every use raised
  `NoMethodError: selector `not``) — `not` is now resolved as the universal,
  non-overridable truthiness negation before any per-kind dispatch; (2) map
  key misses (`Map#[]`, `Map#fetch`) and collection index misses (`[]` on
  Array/Str/Range/LazySeq, `inserted`/`insert!`) now raise rescuable
  `KeyError`/`IndexError` instead of terminal faults; (3) block/lambda
  pattern parameters (`|(a, b)|`, nested `|(x, (a, b))|`) always failed with
  `MatchError` because the emitted param-pattern prologue fell through into
  its own `P_FAIL` after a successful match — the success path now jumps the
  shared fail handler. Block-frame entry additionally enforces RFC
  block-parameters §9.6: fewer positional arguments than declared parameters
  is a rescuable `ArgumentError` (extra arguments continue to be dropped).
  Covered by `not_operator_truthiness`, `key_index_errors_rescuable`, and
  `block_param_patterns` fixtures.
- Implemented the string-tag macro trigger (macro.v1, DESIGN-macro-system
  §8.5): `string_tag macro def sql(t as Ast.StringTemplate)` declares a tag
  macro, invoked as `sql"""…"""` with the text-block opener adjacent to the
  tag (a spaced literal stays an ordinary call). F1.5 classifies the bare-call
  shape by callee + adjacency and hands the macro the literal re-kinded as an
  `Ast.StringTemplate` (post-dedent static chunks plus unevaluated interpolant
  Asts); the macro must return one expression Ast. Tag macros export/import
  like any macro (`export macro sql`, `from db.x import sql as psql`);
  invoking one through an ordinary call channel, `use`, or annotation position
  is a located diagnostic. Covered by the `macro_string_tag` fixture (a
  parameterized-SQL tag), a parse golden, `test_string_tag_surface`, and
  `test_string_tag_macro_staging` (imported/aliased tag + misuse diagnostic).

## Earlier Baseline Summary

- `W0`-`W4`: repository skeleton, deterministic corpus runner, lexer/parser,
  binder/checker, HIR/pattern IR, bytecode schema, serializer, verifier,
  disassembler, and emitter baseline.
- `W5`-`W8`: VM execution core, object lifetime/memory/GC/pinning, scheduler,
  task/channel/sync primitives, module loader, collection runtime, and full
  dynamic conformance runner.
- `W9`: typed checker lane, open-world transactions, reflection mirrors,
  package manifests/locks/artifacts, and hot reload.
- `W10`: advanced concurrency, awaitable bridge, MIR/SSA, native/JIT metadata,
  and frozen image path.

## Closure Work Status

`W13`, `W14`, and `W15` are complete for compiler-contract,
build/bootstrap/conformance, and native-readiness metadata closure. W15 adds
explicit native slowpath metadata, invalidation fallback descriptors,
exception-edge root maps, hardened native validation, and frozen-image readiness
guard verification without changing bytecode VM semantics.
